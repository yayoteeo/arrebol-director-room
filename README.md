### 中控设置

面板顶部的「中控设置」收纳运行／暂停开关和共享设置，首次默认收起，点击标题展开或收起。展开状态沿用抽屉的本地记忆；内嵌面板和弹窗均提供此入口，情感导演、统筹和抽卡页签仍在外面，可直接使用。折叠只改变显示，不会暂停运行或修改设置。

悬浮球打开面板时复用已有界面，不再反复销毁重建；重复点击不会重复打开或绑定事件。重新打开会同步最新设置，并保留滚动位置和临时指令。未切到抽卡页时不刷新整套卡库，切入抽卡页再同步；Anima 状态检查在面板首帧显示后安排，实际分析仍照常实时读取聊天与总结，不缓存 AI 上下文。弹出动画只使用短时位移与淡入，并遵守系统的减少动态效果设置。

### 跟随酒馆主题

展开 **中控设置 → 界面主题**，选择 **跟随酒馆（自动适应自定义 CSS）**。浮窗、内嵌展开内容和放大编辑器使用酒馆的背景、文字、字体、边框及输入框颜色，移除原主题的大面积紫色／粉色渐变与厚重阴影。扩展列表的标题和箭头仍保持酒馆原生样式。

优先读取酒馆扩展面板和聊天输入框的实际计算样式，兼容直接覆盖原生控件颜色的自定义 CSS；无法取到颜色或背景透明时，回退到酒馆的 `--SmartTheme*`、`--mainFontFamily` 等主题变量。修改自定义 CSS、切换酒馆主题、改变系统明暗或窗口尺寸后自动重新取色，无需重开插件；未选择跟随模式时不进行取色刷新。此模式跟随颜色与字体，不会复制自定义 CSS 中只针对特定组件的布局、背景图片或动画。

主题选择自动保存，两套面板同步。原来的朝霞浅色与暗河深色仍可选，旧用户的已有配色不会被强制切换；浮窗右上角的主题按钮也可依次切换 **暗河 → 朝霞 → 跟随酒馆**。主题仅影响界面，不改变聊天读取、AI 请求或注入内容。

回归测试：`node --test test_theme.js test_central_settings.js test_popup.js`。如需运行可选的浏览器测试，将 `ADR_THEME_BROWSER` 设为本机 Chromium／Edge 可执行文件路径后运行 `node --test test_theme.js test_popup.js`；测试仅加载临时的本地虚构页面，验证主题与完整插件反复打开、字段同步、页签和放大编辑。

### 读取 Anima 历史总结

在**共享设置**中勾选「读取 Anima 历史总结」，情感导演和统筹每次分析时都会从当前聊天的世界书读取 Anima 总结，与角色卡、手动补充和最近正文一起发送给各自配置的导演 API。默认关闭，开启后默认读取最近 **20 条总结切片**；可调整条数，填 **0** 读取全部（可能显著增加请求长度和 token 用量）。按批次、切片顺序排列，兼容 Anima 的旧版单条总结。

需要启用 Anima 所需的酒馆助手（`TavernHelper` 世界书接口）。禁用的总结条目也会读取，不要求被世界书激活或被 RAG 检索命中。只接收标记为 Anima 创建且属于当前聊天的总结；分支或复制聊天的旧总结，请先在 Anima 的「历史总结管理」中完成迁移。

**发送位置**：在导演请求中，总结紧接在用户和角色的最近聊天消息之前；角色卡、手动补充、导演日志和投卡史仍在前面。可在共享设置填写「Anima 总结前置用语」，输入自动保存，也可点击「保存前置用语」明确保存到插件设置与本地备份；浮窗和内嵌面板同步，刷新后保留。发送顺序为 **「Anima 历史总结」标题 → 前置用语 → 默认历史资料说明 → 总结正文 → 最近用户与角色消息**。前置用语紧接标题下方第一行，情感导演、统筹、试运行和精准预览使用相同顺序。前置用语可留空；未启用读取、没有有效总结或读取失败时，不会单独发送前置用语。

读取开关下方的小字显示读取状态、实际条数和最近检查时间，两套面板同步。监听世界书更新、绑定设置更新和聊天切换，变化后自动重新检查；开启读取时每 **3 秒**额外检查一次，返回页面时也会刷新。每次发送给导演 AI 前仍重新读取世界书，不使用界面状态或旧总结缓存；更新中的旧请求不会覆盖新聊天或更新后的状态。

在**共享设置 → 校对与诊断 → 预览精准读取**查看前置用语和总结原文。读取状态、条数统计和检查时间仅在开关下方显示，不进入预览正文或 AI 请求。缺少接口、没有总结或读取失败时，导演仍使用原有上下文；不会创建、修改、重新绑定世界书，也不会修改 Anima 数据。未绑定世界书时，仅尝试读取与当前聊天文件同名的已有世界书。

回归测试：`node test_anima.js`（仅使用 Node 内置模块，无需额外安装依赖）。

总结保留编号与原文，并在有有效来源范围时标注楼层，例如 `【总结 10_2｜楼层 20–29】`。缺少或无效的范围不显示，不推测楼层。此来源标注会随总结发送；读取状态与条数统计仍只显示在开关下方。

### 只读取角色消息

**中控设置 → 共享设置 → 额外注入当前聊天首条消息**：默认开启，额外读取当前聊天第 0 楼的实际内容（包括当前选中的开场白及编辑结果），不再把角色卡 `first_mes` 当作聊天开场。每次构造上下文重新读取，无聊天时不回退到角色卡。开关自动保存，内嵌面板与弹窗同步，正式请求、试运行和精准预览使用相同来源。

首条开关独立于回看范围：即使第 0 楼已隐藏、或选择「当前未隐藏楼层」，开启后也会额外读取首楼。优先读取正文标签，未匹配标签时读取整条开场；排除标签和用户消息开关仍生效。优先通过酒馆助手实时读取第 0 楼当前选中版本，接口不可用时回退当前聊天数据，不使用历史缓存或把局部聊天的其他楼层冒充首条。关闭只取消独立的首条消息补充：如果第 0 楼本身在正常聊天读取范围内，仍按普通消息读取。

共享设置新增「读取用户消息」开关，**默认关闭**。关闭时，在提取正文之前排除用户消息（包括带正文标签的用户消息），最近 N 轮按最近 N 条角色消息回看，用户消息不占读取名额；开启后恢复角色与用户消息一起读取。设置自动保存到插件设置和本地备份，浮窗与内嵌面板同步。

此开关应用于导演请求、精准读取预览和抽卡模块共用的最近正文读取，不改变自动触发计数或原始聊天记录。它只过滤直接读取的用户聊天消息，不删除或改写 Anima 总结、角色卡、用户人设和手动补充中已有的信息。

读取到的消息在名字旁标注酒馆原始楼层号，例如 `[角色名｜楼层 30]`、`[用户名（用户）｜楼层 31]`。楼层号沿用消息编号，从 0 开始；优先使用酒馆助手的 `message_id`，原始聊天数据则使用消息在聊天中的索引。隐藏、排除或只读角色消息后不会重新编号，预览与发送给 AI 的标注一致。

### 排除正文中的标签内容

「正文标签名」不再强制默认 `content`：**留空或填 `*` 会读取整层文字，再执行排除标签规则**，即使消息中存在 `<content>` 也不会只选其中一段。只有明确填写 `content`、`story` 等标签名时，才限制读取范围。已有自定义标签会保留；希望只使用排除规则时，清空正文标签即可，空值会保存。

在**共享设置 → 进阶开关**中，「正文标签名」下方新增「排除标签名」。例如正文仍填写 `content`，排除填写 `think, status, note`，则 `<content>剧情正文<status>状态栏</status>后续正文</content>` 只读取「剧情正文后续正文」。排除标签本身及其内部内容，支持多标签、同名嵌套、大小写和带属性标签，中英文逗号均可分隔；留空不排除。

排除在正文提取之前执行，也适用于 `*` 整层读取、开启用户消息后的用户原文、精准预览与正文提取诊断。排除标签未闭合时，从该标签开始到消息末尾都不读取，避免泄漏应排除的内容。设置自动保存，两套面板同步；不会修改聊天原文或 Anima 总结。

### 读取全部未隐藏楼层

在**共享设置 → 导演回看多少楼**选择「当前未隐藏楼层」，会按时间顺序读取当前聊天中所有未被酒馆隐藏的消息，不再受最近 N 轮限制，也不会沿用整层读取的单条文字截断。仍遵守「读取用户消息」开关、正文标签与排除标签设置；用户读取关闭时，只注入未隐藏的角色正文。

每次读取直接查询最新隐藏状态，不使用只按楼层数量判断有效性的历史缓存。因此即使消息数量未变化，隐藏或取消隐藏后，下次分析或精准预览也会更新。兼容酒馆的 `is_system` 与酒馆助手的 `is_hidden` 标记；助手不可用时从当前酒馆聊天数据读取，不回退到旧的历史缓存。此模式不改变自动触发计数，也不改变抽卡小眼睛独立设置的回看轮数。

向酒馆助手查询时先取全部消息，再由导演室排除明确标记为隐藏的楼层。没有隐藏字段的普通消息也视为未隐藏，避免助手的严格筛选将这类角色正文误删。该处理不修改消息的隐藏标记。

“不限数量”可能显著增加请求长度；若超出模型上下文上限，请隐藏不需要的旧楼层或改回固定轮数。

### 导演 API 重试上限

共享设置新增「导演 API 自动重试次数」，默认 **2 次**，可设 **0–10 次**，不含首次请求。例如设为 2 时，同一轮最多请求 3 次；设为 0 时失败后不自动重发。保留原有间隔退避，并让消息事件、定时轮询等所有自动补拍入口共同遵守次数和等待时间，不再收到新消息就绕过等待重复请求。

达到上限后，暂停该聊天中对应导演的自动请求，次数在请求开始前写入聊天状态和本地镜像。新增楼层或刷新页面不会重新获得一轮额度；情感导演与统筹分别计数。检查网络或配置后，可点击「恢复当前聊天的自动请求」清除两位导演的暂停并重新计数。手动停止正在进行的自动请求也会暂停后续补发。

手动「分析」仍由你决定，每次点击只发起一次 API 请求，不额外自动重发，也不会自动解除已暂停的自动请求。此上限针对双导演自动分析流程，不改变抽卡小眼睛的独立调用逻辑。失败重试可能产生服务商费用；需要完全禁止自动重发时设为 0。

### 完整试运行（不花钱）

「试运行」与正式导演请求共用请求体构造函数，在结果框以可读文本分段显示，不再展示带大量 `\n` 转义的 JSON，也不再显示模型、温度、流式开关说明。下方依次展示完整「系统预设 · system」和「发送上下文 · user」，保留原文换行与段落。上下文包含一次性补充、角色卡、世界书、用户人设、当前聊天首条消息（启用时）、手动补充、Anima 总结及前置用语、导演日志、统筹投卡史与按当前规则提取的聊天正文。预览标题、分段标题和参数说明不写入消息正文；真实请求仍保留调用 API 所需的模型、温度、流式参数。

「试运行完成」旁显示字数和估算 Token 数。字数按完整 system/user 正文的 Unicode 字符数统计（包含空白与换行），不计预览标题、参数或统计文字。Token 优先使用酒馆当前分词器逐条统计，接口不可用、异常或超过 2 秒则使用本地粗估，不重试。酒馆分词器不一定与导演的独立模型一致，且不计消息封装开销，因此不是计费精确值。统计仅在界面状态栏显示，不发送给导演 AI。

不再额外截取前 1200 字，也不使用与正式请求不同的简化聊天读取。你设置的总结条数、正文范围、标签排除与用户消息开关仍照常生效。试运行只读取所需资料，不调用导演模型 API、不注入聊天、不清空一次性指令、不结算自动触发进度；API Key 不包含在预览中。未配置 API 也可预览请求内容，真实发送仍需有效的 API 配置。

回归测试：`node --test test_anima.js test_requests.js`（无需安装额外依赖）。

### 导演请求流式接收（v1.27.0–1.27.1）

两位导演的请求改为流式（`stream: true`）。会思考的模型接在导演位上常报错，是因为非流式要等整段思考跑完才回第一个字节，中转站的空闲超时先把连接掐了；现在逐块接收、只把正文拼进稿子、思考只计字数不进稿，状态行会实时写「模型思考中，N 字」／「已收到 N 字」。120 秒超时改成「两块之间」的空闲闸，思考再长也不掐，真断流才报「流式接收中断」。服务端不支持流式、回整份 JSON 的照常能用。若某个中转站对流式请求直接报错，共享设置里把「流式接收导演稿」关掉即可，回到老的整份接收，默认是开的。小眼睛（择池／择卡）那几路不变。

### 放大编辑（v1.26.0）

浮窗和内嵌抽屉里每个文字框右上角都有一枚 ⛶，点开整屏编辑（手机全屏、电脑大弹窗），改完点确定回填，自动保存照常；取消或 ESC 不动原文，Ctrl/⌘+Enter 等于确定。

### 本包配色：琉璃暗河（v1.25.0）

浮窗与酒馆内嵌抽屉整套换皮，只动视觉不动功能：暗河（🌙）是墨靛玻璃面、顶部一抹霞光、卡片带一线内高光；朝霞（☀️）是瓷白纸面、淡粉淡蓝晕、砚蓝墨字。主动作按钮（分析／挂稿／试抽）改为实色霞光渐变，次级按钮退为玻璃描边；输入域收窄一档并加内阴影；开关换成带投影的胶囊；页签成分段控件；计数卡的数字用香槟金。触控命中区与右缘安全缝原样保留。

## 一、剧情小风铃是什么

治长上下文剧情塌缩的土方子：每 N 个助手正文轮次，向模型耳边投一张**"发生了一半的事"**——门房的口信、没熄火的车、被撕走的账页。卡通过独立扩展提示词通道常驻注入（不占楼层，藏楼/摘要洗不掉），下一张到点自动替换。

机器全瞎：数楼、掷骰、贴耳，三个动作，零 API、零延迟、零开销。聪明不在机器里，在卡里——你写卡的时候把智能一次性预付了。

### 两分钟上手

1. 打开 Arrebol D 面板 → 「🎴 抽卡」页 → 勾选**启用剧情小风铃**
2. 出厂自带「通用」卡库（意外/转折/伏笔/代价/外力/狗血六池），到点即投
3. 想换节奏拖 N 滑杆（1–20 楼，默认 5）；关键场景勾**暂停投卡**（按聊天记忆，暂停期间耳机静音）
4. 点**试抽一张**可预览手感——不入投卡史、不注入、不产生费用

### 两种模式

- **盲抽**（默认）：两段抽——先各卡池均等随机，再池内均匀随机＋冷却（最近 M 张不复用，默认 8、最多 32，填 0 就是没有冷却；单池卡数不足时自动降冷却，永不死锁）。天马行空档。
- **择卡**（v1.23.0）：按仓库均摊摸出若干候选，**连卡面一起**给 DS，让它挑最贴合此刻的一张——**必须选一张，没有「都不选」这个出口**（v1.23.0 给过弃权位，结果模型一路空过，一张不投，v1.23.1 拆除）。治的是"池选对了、池内那张不贴合"。NSFW 候选只给标签不给卡面（`【NSFW·池名】（卡面不外传）`），准入仍由双向硬门把关。答复只认数字；越界、夹带解释一律降级盲抽。
- **择池**：接一个便宜模型（推荐 DeepSeek，独立 API 位）当**小眼睛**（这个位置接 DeepSeek、Gemini 或你自选的任何模型都行，面板与日志里一律叫它小眼睛；地址填到版本段即可，`/v1`、`/v1beta/openai`、`/api/paas/v4` 这类都认得。小眼睛的答复额度是 200 个 token，答复本身只要几个字，余量是留给会思考的模型的；思考特别长的模型仍可能回空、被记成"答复无效"而降级盲抽，日志会写明原因，那就换不思考的模型或在服务商侧关掉思考）——**只看卡池名单点池，看不到任何卡面**，池内仍然盲抽。答复多一个字作废。

  择池那次调用喂给 DS 的语境按这个顺序：**【刚刚这一楼】→【再往前几楼】→ 卡池名单 → 最近已投 →【整体调性】**。此刻的氛围只认第一段；前几楼只用来看这股势头是在持续还是已经收场；角色卡与世界书压在最后并截到 2000 字，只用来判断某类情节允不允许发生，**不作为此刻的依据**。

  **必须选一个**：名单里没有「都不选」。即使此刻没有特别贴合的，也要挑最不打断当下的那一个。（v1.23.0 曾给过弃权出口，模型一路走出口导致完全不投卡，v1.23.1 拆除。）

  **防惯性**：同一卡池被连点第 3 次，改在**同一仓库内**换池。情欲场面里连点同一个 NSFW 池正是应该的，踢去全仓库盲抽反而会拿无关卡打断场面。

  **降级会出声**：超时（8s）、解析失败、报错一律当场降级盲抽，抽卡器永不停摆；此时 **NSFW 库一律不参与**（DS 挂了＝没人判准入条件，默认不准入），状态行会直说「⚠ 上一张是 DS 没应答时随机给的」。

### 三个仓库

抽卡器面前摆三格，各自独立勾选：

| 仓库 | 干什么 |
|---|---|
| **专属剧情库** | 配角色卡——写这个角色独有的事（前世债、师门旧账、他特有的毛病） |
| **通用库** | 打底——车票、口信、钥匙这类哪朝哪代都能落的事 |
| **NSFW 库** | 单独一格，默认停用，内容由你自己填 |

> **NSFW 库的准入只由择池模式把关**（双向硬门：此刻确有情欲张力在持续 **且** 故事整体调性允许，两条都满足才选它，任一不满足就当它不在名单上）。盲抽模式没有眼睛，点亮就是 1/N 硬掷——这是明码标价的取舍，不是 bug。唯一的例外是择池失败降级时：那种情况下 NSFW 一律不参与。另一个边界要说清：**只开 NSFW 仓库时，名单里就只有 NSFW 池**，双向硬门无门可把，小眼睛只能在这一格里选——这是用户自己的仓库配置，插件不替用户做选择，只保证名单如实。

**仓库数即权重**：启用哪几格，就在哪几格之间均等掷。专属库只有 1 个卡池、通用库有 5 个，专属库照样占一半出场——这是三段抽的第一段保证的，不会被池多的一边淹掉（桩测两万次实测 50.2%）。

三格都是"选一副卡库挂上去"，同一副库可以挂在不同聊天的不同格里。换聊天各记各的，账号级留一份默认，新聊天开局自动继承。

### 卡库仓储

- 格式祖传：`## 卡池名` 一行开池，一行一张卡，`//` 开头是注释，空行随意。**即改即生效。**
- 卡库按名字管理；编辑区选一副改，改完**保存**（新建或更新）／**重命名**／**删除**。
- 双向门：导入 / 导出 `.txt`/`.md`。**导入时可直接选落点**——挂进哪个仓库，导完就能用；同名不覆盖，自动另开一副。
- 卡面里可以写 `{{user}}`、`{{char}}` 等宏，投卡时替换成当前名字。

### 卡面家法

一张卡 = 一件发生了一半的事，三特征缺一不可：

- **具体**：有人有物有时刻
- **悬置**：谁 / 为何，卡不说，留给演员说
- **可嫁接**：无专名，什么局都能落（专名由统筹在场上现铸）

「门房捎来一句口信：三天前就该到的人，今晚到了」——合格。
「现在发生一个转折」——不合格。

nsfw 池另加一条：写"把房间弄斜的一件事实"——灯没关、门没锁、话说了一半；不写动作说明书。

推剧情、保新鲜这份匀速活移交给了抽卡器——该由"物"干的不再由"评"干。红霞升职**统筹**，四职一次调用打包：

2. **顺场**：转场衔接与流畅度
3. **收线**：盘点伏笔与已投事件卡，点名哪条该兑现——撒出去的钩子不许无限堆积
4. **急诊与验收**：NG 会诊照旧；评估此前指导执行情况

输出纪律（硬性）：带名字带条目——「让老周把口信送到」合格，「推进剧情」退回重写。统筹的采买清单里含**投卡史**（最近 5 张：卡池/卡面/楼层/模式），账房盘账看得见牌桌。

例行巡逻默认关；开启时默认每 20 楼。日常节奏：抽卡器匀速开门，统筹低频收线＋NG 触发＋手动，贵重模型少开火，账单反而降。

存量说明：若你的剧情导演预设从未改过默认值，升级后自动换为统筹说明书；自己改过的预设一律不动。

### 导演的记忆跟着聊天走（v1.24.0）

## 五、卡的生命周期

以前一张卡从投下到被顶掉，全程都挂着「必须发生」——第一楼就写完的事，后面几楼还在耳边催，只能反复强调或假装没看见。现在它有三段命：

| 阶段 | 耳边说的话 | 怎么进入 |
|---|---|---|
| **必须发生** | 以下事件已然发生，织入正文 | 刚投下 |
| **已发生的背景** | 此事已经发生过，可以被提及，但不必再推进 | 挂过 N/2 楼自动（半衰期档） |
| **只说了一次，已撤下** | （耳边清空，留白到下一张） | 挂满一层自动（只说一次档） |
| **已结案** | （耳边清空） | 手动点撤下，或 DS 判定已兑现 |

### 生命节奏三档（v1.20.0）

面板上「这张卡在耳边待多久」一个下拉，三选一：

| 档位 | 行为 | 治什么 |
|---|---|---|
| **半衰期**（默认） | 前 ⌈N/2⌉ 楼「必须发生」，之后换成「已发生的背景」继续挂着 | 原样，老用户升级后行为不变 |
| **只说一次** | 只挂一层，说完自动撤下，耳边留白 N−1 楼，第 N 楼再给新卡 | **模型反复复述同一段剧情** |
| **常驻** | 一直挂到下一张来换，不降级 | 等价于旧版关掉半衰期 |

**为什么需要「只说一次」**：贴耳注入每次生成都会把同一张卡再念一遍——N=10 就是连着念十遍「必须发生某某事」。模型复述好几轮不是它笨，是我们真的念了好几遍。半衰期只放软后半程的语气，念的次数一次没少；这一档把次数直接压到一遍。那一层模型没接住就算了。DS 兑现判定在这档跳过，不产生费用；投卡史记「只说了一次」，不冒充已兑现。

老存档自动迁移：原来勾着半衰期 → 落到「半衰期」；原来关着 → 落到「常驻」。

- **半衰期**：纯本地换一次文本，零 API、零延迟。N=5 就是第 3 楼自动退为背景。
- **一键结案**：读到卡里的事落地了，点「✓ 这张已兑现，撤下」。**基准线不推进**——下一张仍按原节奏来，中间那几楼是留白，让剧情喘口气。
- **DS 自动判定**（默认关）：到半衰期时问一句「兑现没」，只认「是」/「否」，答是就自动撤下。每张卡最多多一次调用，跟择池同频。**判不了就按未兑现降级，绝不误撤。** NSFW 库的卡不问（卡面不出门），到半衰期直接降级为背景。
- **投卡史带状态**：● 挂载中 / · 已退为背景 / ○ 只说了一次已撤下 / ✓ 已兑现，统筹收线时看得见哪条还欠着。

### 信封两段式 + 预设

信封拆成前半程与后半程两套文本，按名管理，出厂四套：**标准**（默认）、**强硬**（加粗禁止复述，对付爱复读的模型）、**轻柔**（只给氛围不给指令，对付被硬指令带跑偏的模型）、**看时机**（v1.23.0）。

「看时机」值得单独说：标准信封写的是「以下事件已然发生。织入正文」——等于命令模型**这一楼就得用**。一张温情卡撞上正在吵架的一幕，崩就崩在这一句。「看时机」保留「必须发生」的分量，只把时点的决定权还给写故事的模型：*若此刻场面不适合它进场，就让它先在背景里发酵，等一个合适的时机再织入正文*。老用户升级后会自动补上这一套（改过的旧信封一字不动；自己删掉的不会复活）。
下拉切换立即生效；改了文本再点保存就写进当前这套。
